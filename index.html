Routing for multi-technology sensor networks

One network, many radios. Each message picks its own road.

RODENT lets a sensor node choose, message by message, which neighbour to send through and which radio to use. A cheap temperature reading goes the slow, frugal way. A frost alarm goes the fast way.

Every radio is a compromise

A farm sensor has a battery and a long way to talk. WiFi is fast but short-ranged and thirsty. LoRa reaches kilometres on a trickle of energy but moves data slowly. BLE is a cheap short hop. Operator networks such as Sigfox or NB-IoT add coverage gaps and subscriptions.

No single radio is right for every node, and not even for every message from the same node. A temperature reading every few seconds wants low energy. A frost alarm wants to arrive now.

RODENT's answer: give each node several radios, let it keep a table of the roads it knows, and pick a road per kind of message.

How a node learns the network

No node ever sees the whole map. Each one builds its table from just two sources: its own radio links, and what its neighbours say about their best roads.

Step through it on the right. We follow N5, which can only hear N4, and watch it end up with a complete road to a base station.

Vocabulary: the link matrix (LM) lists a node's direct links. The route matrix (RM) lists every road it can use. A requirements vector (RV) is the weight set for one kind of message.

How a node chooses

With several roads available, the node must rank them on several criteria at once. RODENT uses TOPSIS: score each road by how close it is to the ideal and how far from the worst, with the message's weights deciding what counts.

Classic TOPSIS has a flaw for radios. It rescales each criterion using all candidates, so when an unrelated neighbour appears or vanishes, two roads can swap places and the node switches radio for nothing. The thesis measured this in about 30% of cases for a 5×5 decision matrix.

RODENT normalises against fixed bounds of each radio instead. The yardstick never moves, so the order cannot flip, and the maths gets cheaper too.

      What is in a packet

      Every RODENT packet carries the routing information with it. The header names the network, the sender and the next hop, then says which kind of message this is, then carries the sender's best road as four bytes: energy, money, speed, hops.

      That last part is the trick. Every neighbour that overhears the packet learns a road for free, with no separate routing message. The fixed overhead is only 9 bytes, plus one byte per criterion.

      Edit the fields and watch the bytes and the CRC-8 checksum change. Hover a byte to see its meaning.

      When things break

      Roads are only believed while they are being refreshed. Base stations send a small beacon every couple of seconds, and nodes keep re-announcing their roads. If a beacon stops, the link is declared dead (7 s in our lab firmware). If a neighbour goes quiet, the road learned from it expires (14 s).

      Break something and play the failure. Notice the middle stage: right after the base station dies, a relay can still believe in a neighbour's stale road until it times out.

      The classic WiFi-only protocol has no such detector: its nodes keep transmitting into the void.

      What the thesis measured

      Five FiPy boards, WiFi + LoRa + BLE, two base stations, 20 runs of 10 minutes each. These are the author's results.

      0% → ~80%Delivery for N5, the isolated node, once RODENT lets it relay through N4. N2 and N4 also reach about 80% on LoRa.
      > 95%Delivery with the "improved" version that sends each LoRa message twice and each BLE message three times. The author traces the losses to the prototype hardware and raw radio modes, not to the protocol design.
      ~30%Of 5×5 decision matrices cause a rank reversal in classic TOPSIS, and it gets worse as matrices grow.
      82%Of runs, RODENT's cheaper decision picks the same road as classic TOPSIS.
      Mean time to rank a 5×5 decision matrix on the node: classic TOPSIS 4.79 ms, RODENT 2.96 ms (about 38% faster on average). The author estimates roughly 448 µJ saved per ranking. Energy figures are estimates from datasheets, because direct current measurement on the FiPy boards was unreliable.

      What RODENT does not do

      It is a routing layer, and it leans on assumptions worth knowing before you build on it.

      • Link discovery is assumed. Lower layers must measure link cost, quality and availability. In the prototype the link matrix is written by hand.
      • Convergecast only. Messages flow from sensors to a base station, not from node to node.
      • Bigger packets. Every packet carries routing bytes, which costs a little airtime.
      • Beacons are a cost. Rarely used roads need periodic control packets to stay alive.
      • Small, indoor prototype. Five nodes, three radios, a lab. Field trials with partners were cancelled by the pandemic.
      • Prototype losses. The measured delivery dropped versus WiFi-only; the author attributes it to engineering, not design.
